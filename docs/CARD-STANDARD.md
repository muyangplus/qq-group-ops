# 卡片标准（Card Standard）

> 适用范围：**所有 QQ 端指令输出**。新增指令必须遵循；改造旧指令时按本标准逐条对齐。
> 实现位置：`src/services/cardTemplate.ts`（渲染）、`src/services/callbackData.ts`（回调编码）、
> `src/services/callbackRouter.ts`（回调分发）、`src/services/richMessages.ts`（投递与降级）。

## 1. 一切输出都是卡片

- 所有指令回复都通过 `renderCard()` 生成 `RichMessage`（Markdown + 按钮 + 纯文本降级），
  由 `RichMessageSender` 投递：**Markdown+按钮 → Markdown → 纯文本** 三级降级。
- 卡片结构固定：`## 标题` → 正文行 →（有按钮时）按钮引导行 → 按钮行 → 底部提示。
- **禁止手写 `keyboard` JSON**：按钮一律用 `CardButton` 声明，行数（≤5）、每行文字总长（≤12 字）、
  按钮文字长度（≤10）、按钮 id 唯一性由模板统一校验。
- **兜底保证**：`AdminCommandService.ensureCard` 会把任何还不是卡片的指令结果（含用法提示、
  权限提示、错误提示）统一包成卡片，因此"所有指令输出都是卡片"是**代码层不变量**，并有测试锁住；
  为某条指令做定制卡时，替换它自己的 handler 即可。

## 2. 按钮类型（混合标准）

| 用途 | 类型 | 写法 | 行为 |
|---|---|---|---|
| 导航 / 查看 / 翻页 / 刷新 | **回调按钮** | `callbackData: encodeCallback(ns, action, ...args)` | 点击即回包 + 主动发新卡片，用户不用再发消息 |
| **固定动作**：无需参数、结果确定（通过审批、开关切换、枚举取值） | **回调按钮** | 同上 | 点击即**自动完成**，并回一张**刷新后的**卡片 |
| 需要自由文本/数值的动作（拒绝原因、关键词、警告文案、禁言时长、绑定） | **指令按钮** | `command: "/xxx ..."` | 点击=发送该指令，用户可先补参数再发 |
| 影响大 / 不可逆的动作（移出群、拉黑） | 指令按钮 + `modal` | 同上 | 二次确认后才发送 |

判断顺序：**能自动完成就用回调（开关类、枚举值全走回调）；需要人补参数就用指令按钮；不可逆动作再加二次确认**。

### 2.1 回调动作必须有反馈，并标明操作人

- 回调自动完成的动作**不能静默**：必须回一张**刷新后的**卡片，正文顶部给出结果行，
  例如群内回复以 `<@!点击者openid>` **单独一行开头**，随后是 `**结果**：已通过 #M7K2Q9`、
  `**结果**：已更新：joinDecision = approve_on_match`；私聊里不 @（操作人就是接收者本人）。
- **操作人用 `displayUser(userId)`**（只显示 QQ号 / 短码，不暴露 openid）——群内多人能看到同一张卡，
  必须能看出是谁点的；
- 失败时同样给反馈（`权限不足` / `规则未修改` + 原因），不要静默失败。

理由：导航类用回调体验最好；固定动作用回调省掉一次输入；而带参数/不可逆动作必须与手输指令共享
同一条权限与审计路径，避免"点按钮绕过校验"。
**回调 renderer 内部必须重新做权限校验**；回调按钮没有可复制的指令，
手动指令统一在 `/help`（及主题）里提供，卡片不再罗列；列表分页的 `+页码` 提示保留。

**固定指令的一键入口**：用 `encodeCallback("cmd", "run", "/<指令>")` 把一条**不带参数**的固定指令
包装成回调（例如 `cb:cmd:run:/myperm`）。它复用 `AdminCommandService.handle`，权限、审计、
二次确认与手输完全一致；菜单里 `/myperm`、`/profile`、`/audit`、`/notify`、`/perm list` 等
入口都用这一招接入，新指令无需额外 renderer。

## 3. 分页

- 列表类指令必须分页：默认每页 10 条；条目多行时按需减少（如 `/pending` 每页 3 条）。
- 卡片按钮：`[上一页] [下一页] [刷新]` 全部是回调（`cb:<ns>:page:<参数>:<页码>`）。
- 页码写进正文：`第 2 / 3 页 · 共 12 条`。
- **纯文本降级必须能翻页**：正文底部给出 `+页码` 形式的指令，例如
  `/pending +2`、`/audit 20 +2`、`/pending 654321 +2`。
  用 `+` 前缀是为了不与群号/短码参数冲突（群号是纯数字）。

## 4. 降级

- `RichMessage.text` 必须**自包含**：标题、关键信息、以及每个按钮对应的**可复制指令**。
- 按钮不可用时，用户仅靠纯文本也能完成同样的操作（翻页、审批、开关规则）。
- 回调按钮没有可复制的指令，因此正文里必须给出等价的指令入口。

## 5. 权限

- 入口按权限过滤：看不到的能力不生成按钮。
- 越权（指令或回调）必须给出明确原因，不能静默失败。
- 回调 renderer 与指令 handler 复用同一套权限判断，避免两套逻辑漂移。

### 5.1 隐私结果只走私信

涉及隐私或真实系统 id 的结果（代表：`/whois`、`/whois profile`）**只发私信**：

- 私聊里发指令 → 直接回复；
- 群聊里发指令且私信成功 → **群里完全静默**（`silent: true`，连「已私信发送」都不回）；
- 私信通道失败（对方没私聊过机器人、未开启主动消息）→ 群里回**唯一一条**不含结果的提示
  「请先私聊机器人再试」，**绝不降级到群里显示结果**；不含隐私的失败提示（权限不足、用法、未找到）照常群里回；
- 目标是群内成员时，允许用官方 at 段（`<@!openid>`）指定；`@昵称` 反查不到就明确提示替代写法，不猜。

## 6. 文案与排版

- **每行按钮文字总长 ≤ 12 字**（模板已强制校验）——按钮**个数**不做硬性限制，
  但官方上限是一行 5 个、整盘 5 行；
- **开关类按钮一行 2 个**：标签写成「2-4 字描述 + 开/关」（如「过滤 关」「入群 开」「撤回 开」）；
- **枚举类**：标签 2-5 字，当前值用 `● ` 前缀 + 高亮样式标出（一行 2-3 个）；
- 单个按钮文字 ≤ 10 字（官方硬限制，模板会截断）；
- 整个键盘最多 5 行 —— 按钮多到放不下时**不要硬塞，拆成子卡**
  （例：`/rules` = 概览 + 开关设置 / 入群决策 / 命中处罚）；
- **按钮已经完全表达的开关/枚举状态，不要在正文里再用大段文字重复展示**；正文只保留按钮没覆盖的字段（自由文本、数值、说明）；
- 标题 ≤ 20 字符；正文单行 ≤ 100 字符；用户可见标识只用已绑定的 QQ号 / 群号 / 短码，不暴露 openid。

## 7. 测试与文档

每条指令至少覆盖：

- 卡片渲染：标题、正文关键行、按钮类型与 `data`/`command` 正确；
- 权限过滤：无权用户看不到入口，越权调用有明确提示；
- 纯文本降级：正文包含可直接执行的指令，分页指令可用；
- 分页边界：第 1 页没有「上一页」、最后一页没有「下一页」、页码越界收敛。

同时：`helpTopics.ts` 必须有对应主题；README / CONFIGURATION / ACCEPTANCE 同步更新。

## 8. 新增指令检查清单

- [ ] 输出走 `renderCard()`，不手写 keyboard
- [ ] 导航/查看/翻页按钮用 `cb:` 回调；动作按钮用 `command:`
- [ ] 列表有分页，且纯文本降级能翻页（`+页码`）
- [ ] 权限过滤 + 越权提示
- [ ] `text` 自包含、可直接复制执行
- [ ] 测试（渲染 / 权限 / 降级 / 分页边界）
- [ ] `helpTopics` 主题 + README/CONFIGURATION/ACCEPTANCE
