# 真机跑批手册（一次跑完 R2–R18 + 交付验证）

> 配套文件：[REAL-MACHINE-CHECKLIST.md](./REAL-MACHINE-CHECKLIST.md)（每项的背景与判定标准）、
> [ACCEPTANCE.md](./ACCEPTANCE.md)（J 系列 66 条详细验收）、[OPERATIONS.md](./OPERATIONS.md)（启动与排障）。
>
> **用法**：按下面顺序做一遍，把每步的「回填」行填好，最后整段贴回来即可 —— 不需要你现场判断对错，
> 只要描述**你看到的现象**（截图更好）。

## 0. 准备工作（5 分钟）

| # | 准备项 | 说明 |
|---|---|---|
| 0.1 | `.env` 填写完成 | 见 [CONFIGURATION.md](./CONFIGURATION.md)；`ADMIN_USER_IDS` 至少 1 个超管；决定用 SQLite（默认）还是 PostgreSQL |
| 0.2 | 构建 + 启动 | `pnpm build` → `pnpm start`（或 `pnpm dev`，dev 默认 `LOG_LEVEL=DEBUG`） |
| 0.3 | 确认启动成功 | 日志出现 `gateway ready: bot authenticated` |
| 0.4 | 准备 3 个账号 | **超管**（`ADMIN_USER_IDS` 里那个）、**群管理员**（用小号在群里设为群管理，或用 `/perm grant admin`）、**普通成员小号**；小号都要能在群里发言 |
| 0.5 | 记录日志起点 | `wc -l logs/qq-group-ops.log` —— 跑完后用 `tail -n +<行号>` 只看新日志，避免翻旧内容 |
| 0.6 | 建一个**临时测试群** | R10 / R11 / R13 会改群配置，别拿正式群跑；跑完直接把群归档 |

一次性取证命令（跑批过程中/跑完后执行，把输出贴回来）：

```bash
grep "mention probe" logs/qq-group-ops.log                  # R1/R16：@全体 原文形态与是否被短路
grep "unhandled official event" logs/qq-group-ops.log       # R2/R18：官方推了哪些没实现的事件
grep -E "gateway ready|identify|ERROR|WARN" logs/qq-group-ops.log | tail -40   # 启动与异常
```

## 1. 顺序跑批（建议一次做完 ①→⑩）

### ① R16 `@全体` 不再抢答（B3）

| 步骤 | 群里依次发 |
|---|---|
| 1 | `@全体成员`（不带任何内容） |
| 2 | `@everyone` |
| 3 | `@全体成员 大家好` |
| 4 | `@全体成员 /menu` |
| 5 | 空 `@机器人`（只 @ 机器人，不带内容） |

**回填**：①②机器人是否完全不出声（Y/N）；③是否按普通发言处理；④是否出菜单；⑤是否出常用菜单；
`grep "mention probe"` 的输出。

---

### ② R18 好友申请 / 机器人被拉进群（A2）

| 步骤 | 操作 |
|---|---|
| 1 | 用**小号加机器人为好友** |
| 2 | 把**机器人拉进一个新群**（或先踢出再拉回） |
| 3 | `grep "unhandled official event" logs/qq-group-ops.log` |

**回填**：有没有出现 `C2C_FRIEND_ADD` / `GROUP_ADD_ROBOT` 之类的事件（把整行贴回来，含 `dataKeys`）；
一条都没有也照实说 —— 我会加 intent 覆盖项再试。

---

### ③ R2 用户撤回消息有没有事件（B7 扩展）

| 步骤 | 操作 |
|---|---|
| 1 | 小号在群里发一条普通消息，然后**撤回**它 |
| 2 | 再看一次 `grep "unhandled official event"` |

**回填**：有没有新事件类型出现（贴整行）；没有就说「无」。

---

### ④ R3 内容安全 / 媒体审核接口是否存在（B4/B5）

| 步骤 | 操作 |
|---|---|
| 1 | 开放平台后台 → 机器人 → **开发设置 / 权限**，逐项找：`内容安全`、`消息审核`、`文本审核`、`图片/媒体审核`、`msg_sec_check`、`敏感词` |
| 2 | 有任一项 → 点进去抄下**权限名 + 接口路径**；都没有 → 到文档站 api-v2 搜一次 `sec_check` / `内容安全` |

**回填**：有 / 无；有的话给权限名与接口路径。

---

### ⑤ R4 官方群拉黑接口（A5）

| 步骤 | 操作 |
|---|---|
| 1 | `/blacklist add <小号QQ号>`（小号需先在群里） |
| 2 | 看返回卡与日志里 `updateMemberBlacklist` 的结果 |

**回填**：成功 / 失败（失败请贴错误信息，如 `11253` / `400 应用无接口访问权限`）。

---

### ⑥ R5–R7 隐私与交互（`/whois`、菜单、@ 位置）

| 步骤 | 操作 | 看什么 |
|---|---|---|
| R5 | 群里发 `/whois <某人>`；再换一个**从没私聊过机器人**的号发一次 | 前者群里是否**一条消息都没有**；后者群里是否只有一条「请先私聊机器人再试」（且不含结果） |
| R6 | 普通成员群里发 `/menu`、空 @机器人；管理员群里发 `/menu 管理`；超管群里发 `/menu 超管`、私信发 `/menu` | 默认是否「常用菜单」；**群里是否完全看不到管理/超管按钮**；超管菜单是否被要求在私信使用；私信里对有权者是否出现管理/超管按钮 |
| R7 | 群里发 `/menu`、`/status`、`/rules`；点一次群卡上的「刷新」；再发 `/test`、`/testmenu`；私聊发 `/menu` | 每条群回复的**第二行**（标题下一行）是否是 `<@!你>` 且真能 @ 到人（含回调回复）；`/test*` 与私聊是否不加 @ |

**回填**：R5/R6/R7 各一行：符合预期 / 差异描述。

---

### ⑦ R8–R9 处罚推送、黑名单与申诉闭环

| 步骤 | 操作 |
|---|---|
| R8-1 | 群管理员或审核员私信 `/notify punish on` |
| R8-2 | `/rules set punish 警告,撤回,禁言`（或在「违规处理」子卡上点开关），小号在群里发一条命中关键词的消息 |
| R8-3 | 审核员私信应收到处罚卡；点「禁言时长 → 1 小时」「解除处罚」 |
| R8-4 | 小号私信 `/appeal <#处罚短码> 误判`；审核员卡上点「通过申诉」/「驳回申诉」 |

**回填**：处罚卡是否收到；点按钮是否生效（禁言/解除）；群里是否**没有**处罚通知；申诉在群里是否完全静默、
审核员是否收到申诉卡、处理结果是否回到申诉人私信。

---

### ⑧ R10–R12 规则与导出（用临时测试群）

| 步骤 | 操作 |
|---|---|
| R10 | 群里 `/rules` → 进「开关设置」子卡点一个开关 → 点「恢复本页继承」（确认）→ 再点「恢复全部继承」 |
| R11 | `/rules add regex \d{8,}`，小号发 8 位数字；再 `/rules add whitelist <小号QQ>`，同样内容再发一次 |
| R12 | 群里 `/export audit 20` |

**回填**：R10 按钮标签是否显示当前状态、恢复后是否回落且重启后保持；R11 第一次是否处罚 + 写审计、
加白名单后是否完全不处理；R12 群里是否静默、私信是否收到脱敏 CSV。

## 3. 排查速查

| 现象 | 先看 |
|---|---|
| 机器人完全没反应 | `/status` 看「全量消息模式」；群里是否开启了接收所有消息；日志有没有 `dispatch` |
| 卡片没按钮 | 日志搜 `custom keyboard rejected`；沙箱 / 未开通接口的错误**不会**丢键盘（0.14.1 起按目标分开记录） |
| 收不到入群推送 | `/notify` 是否开启、是否有审批权限、是否 `/bind qq` |
| 审批后没进群 / 踢人失败 | 日志 `approve` / `batch_remove_members` 的返回码（`11253` 表示接口未对普通机器人开放） |
