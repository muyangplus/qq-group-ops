# Data Compliance

> 本文是工程侧数据合规建议，不构成法律意见。正式上线前应咨询法律/合规专业人士。

## 基本原则

- **最小必要**：只处理实现群管理、审核和审计所必需的数据。
- **目的限制**：数据只用于群管理、安全审核和审计追溯。
- **保存期限**：设置明确过期时间，到期自动删除。
- **访问控制**：最小权限、操作留痕、敏感数据不公开。
- **默认不保存原文**：消息原文默认不落库；需要追溯时短期保存。

## 默认保留策略

| 数据类型 | 默认保留 | 说明 |
|---|---:|---|
| 消息原文 | 0 天 | 默认不保存；可配置为 3–7 天短期保存 |
| 规则命中记录 | 180 天 | 只保存规则 ID、动作、时间和伪匿名用户 ID |
| 审核记录 | 180 天 | 入群审批、人工处理结果、操作人 |
| 管理操作日志 | 365 天 | 谁在什么时间对哪个群执行了什么操作 |
| 班级 / 专业索引 | 本地文件 | 由 `data/class.json` 生成；只含班级名单与专业信息，**不含姓名**，且已被 `.gitignore` 排除 |
| 聚合统计 | 长期 | 不包含可识别个人的原文 |

以上均通过环境变量配置，生产环境必须显式设置。

## 持久化与内存缓存

默认使用 SQLite 文件（`data/qq-group-ops.db`），也可以切换到 PostgreSQL。绑定关系、权限、审计记录、入群申请、群配置（含扩展键值配置）、全量消息模式和活动报名都会落库。当前实现采用「内存缓存 + 写穿透」：

- 启动时会把审计记录和入群申请**全量载入内存**；`RetentionService` 会在启动时以及每 24 小时按 `AUDIT_LOG_RETENTION_DAYS` 清理过期审计记录与已审批申请（待审批申请保留），内存缓存与数据库同步清理；
- 写入在回复用户前和进程退出前落库，正常重启不会丢失数据；进程被强杀（SIGKILL）时最多丢失尚未落库的极少量写入；
- `DATABASE_URL=memory` 时为纯内存模式，重启即丢失全部状态，只适合本地调试；
- 项目默认不保存消息原文，因此 `RAW_MESSAGE_RETENTION_DAYS` 当前没有对应数据。

SQLite 场景的额外注意事项：

- `data/` 目录包含用户与群的绑定关系、审计记录等个人信息，不要提交到 Git，也不要放到共享目录；
- 备份前建议先停进程（WAL 模式下冷拷贝才安全），或使用 `sqlite3 data/qq-group-ops.db ".backup 'backup.db'"`；
- 删除个人信息时，需要同时清理 SQLite 主文件和 `-wal` / `-shm` 文件，或执行 `VACUUM` 后确认数据不可恢复。

## 告知与同意

- 在群公告、群规或欢迎语中说明机器人会处理消息用于群管理与安全审核。
- 如需保存原文或使用第三方 AI，应提供更明确的告知。
- 对内部团队群，也应让成员知情；内部使用不等于豁免。

## 第三方内容安全 API

使用前确认：

1. 数据是否用于训练或改进服务。
2. 数据保留期限。
3. 是否支持删除请求。
4. 是否涉及数据出境。
5. 服务商的合规资质与数据处理协议。

优先选择境内服务；如使用境外 API，需要评估数据出境合规要求。

## 安全措施

- 全链路 HTTPS。
- 数据库不暴露公网。
- 数据库备份加密。
- 管理后台登录鉴权、限流、IP 白名单或 2FA。
- 管理员操作审计。
- 密钥通过环境变量或 Docker secrets 注入，不提交到 Git。

## 活动报名与信息导出

- 活动报名只收集活动所需的必要字段，例如昵称、报名选项和联系方式（如确需）。
- 导出属于高风险操作，必须有权限校验、操作审计和脱敏策略。
- 导出文件应设置过期时间，避免长期散落在个人电脑或聊天记录中。
- 报名数据默认只对活动管理员开放，不默认对全体群成员开放。
- 如果导出包含手机号、身份证号等敏感信息，必须单独授权、加密存储并评估合规风险。

## 删除与导出

- 提供按群、按用户、按时间范围的删除能力。
- 用户提出删除请求时，能定位并删除相关个人信息。
- 提供审计日志导出，便于内部审查。

## 个人信息保护影响评估（PIPIA）

以下情况建议进行 PIPIA：

- 长期保存消息原文。
- 处理敏感个人信息。
- 使用自动化决策，例如 AI 自动拒绝入群或自动处罚。
- 向境外提供个人信息。
