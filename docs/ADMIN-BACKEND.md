# 管理后台功能覆盖计划

> 目的：把机器人**已有的全部功能**列成一张表，按优先级决定哪些搬进管理后台、按什么口径搬。
> 待办条目见 [TODO.md](../TODO.md) §5；API 形态与门槛见 [ADMIN-API.md](./ADMIN-API.md)；
> 已落地的部分见 [CHANGELOG.md](../CHANGELOG.md) 与管理后台的「配置 / 状态」页。
>
> 当前进度（0.24.1）：**只读面基本补齐**（状态 / 周期任务 / 配置 / 审计 / 待审批 / 规则 / 活动 / 话题），
> §3 的 **P2 写操作已全部落地**：入群审批、规则单字段 / 关键词 / 恢复继承、活动开关 / 创建 /
> 发布群绑定 / 字段编辑、配置热改项、处罚动作、黑名单增删、申诉复核、别名表、通知门槛。
> 剩下的只有 **P3**（权限授予 / 撤销，`/perm`）与明确不搬的能力边界（§4）。

## 1. 三条口径（为什么按这个顺序排）

1. **先看得清，再能动手**：只读页面是写操作的**前置**——处罚 / 黑名单 / 申诉在后台先有「是什么、
   谁做的、什么时候、现在什么状态」，才谈得上在浏览器里点。反过来（先做按钮）只会放大误操作；
2. **不可逆动作必须二次确认 + 写审计 + 说清后果**：后台已经有一套现成做法
   （`ModalDialog` + `admin_api:*` 审计 + 与指令层同一个领域入口），新写操作一律沿用，
   不新造第二条通路（ADR-0056 第 4 条）；
3. **「权限的权限」最后做**：`/perm`（授予平台超管 / 群管 / 审核员）能改的是**判定权限的那张表**，
   一旦误点影响面最大，排在写操作的最后一档；`/data`（删除 / 匿名化个人数据）**明确不搬** ——
   它是用户自助权（见 §4）。

顺带一条工程口径：**后台的写操作一律调与指令层相同的领域服务**（`JoinApprovalService` /
`PunishService` / `BlacklistService` …），因此权限判据、通知话术、审计记录天然一致，
不会出现「后台写进库、机器人内存态还是旧的」或「两边话术不一样」。

## 3. 优先级

### P1 — 只读补齐 + 零风险写（✅ 已完成，0.24.2 起）

判据：**全部是已有服务的读路径**（或幂等拉取），做完「看得清」这件事就闭环了。
落地：端点与门槛见 [ADMIN-API.md](./ADMIN-API.md) 的 **E1-i**，页面见 `web/src/views/` 的
`PunishmentsView` / `BlacklistView` / `AppealsView` / `DeliveriesView` 与「状态」页的运维区块。
**能力边界**：这些端点只有机器人进程内那口装配（只读巡检模式回 503）；
写操作（处罚 / 黑名单 / 申诉复核 / 活动增删改）仍然只在机器人里做 —— 见下面 P2。

| 条目 | 落点 | 口径要点 |
|---|---|---|
| 处罚记录只读 | `GET /api/punishments?group=&status=` + 「处罚」页 | 默认只看本群、最近 N 条；显示动作 / 时长 / 原因 / 操作人 / 关联短码 |
| 黑名单只读 | `GET /api/blacklist?group=` + 「黑名单」页 | 本群与全局分两组；显示生效范围、加入者、原因、时间 |
| 申诉只读 | `GET /api/appeals?group=&status=` + 「申诉」页 | 显示剩余时限（`APPEAL_HOLD_MINUTES`）、当前值班审核员、是否超时转派 |
| 审批资料摘要 | `/api/pending` 每项附 `profile` 摘要 | 姓名 / 学号（默认脱敏）/ 班级 / 学院 / 年级，与 /profile 同一份数据 |
| 申请队列同步 | `POST /api/join/sync { group }` | 幂等；与 `/sync` 同一服务；写审计 |
| 审计导出 | `GET /api/audit/export.csv` + 页面上一个按钮 | 与 `/export audit` 同口径：默认脱敏、`?full=1` 要 240 并写审计 |
| 运维只读补全 | 扩 `/api/tasks` 或新增 `GET /api/health` | 模块健康 / 降级原因 / 写队列计数 / 迁移问题详情（`/status proc` 的内容）+ 启动期降级报告与回滚回执（现在只私信超管）|
| 通知投递只读 | 新增 `GET /api/notify/deliveries?topic=&status=` | 谁收到了、失败原因、重试次数；排查「我说了怎么没通知」 |

### P2 — 写操作（✅ 已全部完成，0.24.2 起）

> 口径与理由见 [DECISIONS.md](./DECISIONS.md) 的 **ADR-0058**
> （与指令层同源、不可逆动作二次确认、逐条写 `admin_api:*` 审计）；端点与门槛见
> [ADMIN-API.md](./ADMIN-API.md) 的 **E1-j**（处罚 / 黑名单 / 申诉 / 规则 / 通知 / 别名）
> 与 **E1-k**（活动创建 / 发布群 / 字段编辑）。
> 活动字段的操作口径统一收在 `src/services/activitySettings.ts`：字段表（含中文别名 / 输入类型 /
> 能否 `clear`）+ 解析 + 执行（含「满员广播」「变更私信」两个连带副作用），指令层与管理后台
> 调同一份 —— 两边行为不会再各写一套。

判据：**会改变用户状态**，需要二次确认、通知话术、审计三件套齐备。每条动手前把口径写进 TODO 明细。

| 条目 | 门槛 | 口径要点（动手前必须定） |
|---|---|---|
| 处罚动作（警告 / 撤回 / 禁言 / 踢出 / 解除 / 改时长） | 120 | 不可逆动作（踢出 / 拉黑）用两步确认；是否同时在那条处罚的群内发卡（指令层会发） |
| 黑名单增删（本群 / 全局） | 120 / 240 | 全局生效范围提示（所有绑定群） |
| 申诉复核（通过 / 驳回） | 120 | 驳回要理由；通过是否撤回处罚（现在的口径是什么就照搬） |
| 活动创建 / 编辑 / 绑定群 / 解绑 | 130 | 创建后是草稿态并自动绑定创建群，`open` 才广播；字段编辑与「满员广播 / 变更私信」复用指令层的同一套解析 —— 四条都**已落地** |
| 规则关键词逐条增删 + 恢复继承 | 130 / 240 | 恢复继承是不可逆的覆盖删除，要二次确认 |
| 通知门槛调整 + 测试推送 | 240 / 自助 | 门槛是全局的，改完立刻影响所有群；测试只发给自己 |
| 别名表增删 | 240 | 改错会影响匹配，先给预览 |

### P3 — 高风险 / 低频 / 建议不搬

| 条目 | 结论 |
|---|---|
| `/perm` 授权 / 撤销（super / gsuper / admin / mod） | **✅ 已做**（ADR-0060）：只有平台超管 240 能改；二次确认写明「谁多 / 少了什么角色」；**不许撤销自己的全局超管**；每条写 `admin_api:perm_grant` / `perm_revoke` 审计 |
| `/restart`、部署取消 / 立即重启 | **只读展示，不搬写**：会短暂离线，留着在机器人里点更安全（后台显示「有待重启的部署 + 计划时间」已经做了） |
| `/migrate` | **不搬**：一次性不可逆数据迁移，需要看预览卡 + 弹窗确认，留在私信里更合适 |
| `/bind user` / `/bind groupid`（代绑任意主体） | **不搬写**：后台只读展示「群号 ↔ 群 ID」「QQ号 ↔ openid」映射 |
| `/alias`（见 P2 末） | 归 P2 |
| `/data delete / anonymize` | **不搬**（§4） |

## 4. 明确不搬的（能力边界）

- **`/data`（个人数据导出 / 删除 / 匿名化）**：这是**用户自助权**，而且 API 侧一直有
  「不暴露消息原文」「不在浏览器里做平台级个人数据处理」的口径（ADMIN-API.md §4）。
  后台只保留「审计里能看到谁在什么时候做过这件事」；
- **个人资料 `/profile` 的修改**：用户自助；后台只在审批 / 名单里**只读**用到；
- **`/help`、`/menu`、`/test*`、`/testat`**：面向聊天窗口的交互与自检，搬进后台没有意义；
- **`/admin login` / `/admin status`**：`/admin login` 是后台的入口本身（签发一次性令牌），
  不能反过来由后台触发。

## 5. 与现有决定的关系

- ADR-0056 定的是「**能改的只有热改项**、密钥不回传值」；本计划**不改变**这条 ——
  §3 里的所有写操作都不是「改 `.env`」，而是领域动作（处罚 / 黑名单 / 申诉 / 活动 / 权限），
  走的仍然是各自的服务入口；
- ADR-0057 与后台无关；
- 「后台不提供指令层写操作」这条边界由本计划**细化**为三档：P1 里没有写操作（除幂等同步），
  P2 逐个定口径后做，P3 里「重启 / 迁移 / 代绑 / 个人数据」明确不搬。
